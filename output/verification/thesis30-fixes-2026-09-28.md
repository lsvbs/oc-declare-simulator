# Implemented fixes and verification — 28 September 2026

This completes items 1–3 and the algorithm replacements requested after the thesis-30 review. The experimental placeholder values in item 4 were not edited.

## Precedence

EP now checks the Cartesian product of Each objects. Every assignment intersects all required All groups and all Any-group event unions. Both the minimum and maximum bound the number of qualifying earlier events. The primary-object prefilter uses the same predecessor upper bound and does not bypass guard exemptions.

The three original reproductions now reject B: missing cross-type Each combinations, insufficient predecessors for one object, and too many predecessors under a finite upper bound. A separate regression allows repeated B events when the predecessor count still satisfies [1,1]. New objects have no predecessor history; empty Each domains remain vacuous and empty Any groups match nothing.

Canonical counts are used as declared. Per-endpoint observed occurrence statistics no longer silently replace them in Python or the frontend. Current editor changes to types, endpoints, bounds and single-type scope reach the simulator and evaluator consistently.

## DF and DP

Internal discovery, canonical dictionary import, external arc-list import, and the legacy direct_response/direct_precedence aliases now reach the direct temporal checkers. External imports preserve every object label through the editor round trip.

Direct discovery and execution apply joint object filters before finding the nearest strictly later/earlier timestamp. All events at that timestamp remain candidates for counting; a partial All match is outside scope, and Any uses the union before selecting the nearest time.

DF creates response obligations with activation identity and time. Equal-time completions cannot discharge future obligations. Final admission validates the sampled completion and existing reservations, including protecting an already scheduled DP event against a newly proposed intervening completion. Rejected temporal reservations restore the random-generator state before allocating objects or links. The discrete-event completion/arrival/calendar/deadline loop itself is unchanged.

## Scope of the result

These changes are verified fixes to the requested paths, not a guarantee that every discovered model can produce a complete conformant log. AS remains a post-run evaluation constraint; future obligations can remain unresolved at a configured stopping limit or be violated by the existing unrelated-deactivation policy. Direct involvement uses object types, not indirect relationship-path labels. Finite ordinary EF upper bounds still use the existing conservative lifetime admission guard; that guard can restrict valid behavior and should be described as an execution restriction, not as a general exact future-window implementation. Direct windows with larger positive minima may be infeasible under object exclusivity; there is no search for a globally feasible continuation.

Changing formal bound interpretation can change generated behavior. Regenerate any simulation/evaluation results intended for the final thesis using the finalized code and record their model and configuration. The large production experiments were not rerun as part of this targeted verification.
