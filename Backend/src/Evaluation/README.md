# Notebook-aligned evaluation

The Evaluation tab calls `POST /api/evaluation/notebook`. It evaluates the full
saved OCEL 2.0 JSON logs using the numerical definitions in the supplied
`evaluationmeasures.ipynb`. It does not use the truncated object-trace preview,
simulation-internal durations, or the older approximate evaluation endpoints.

`notebook_measures.py` contains the ported notebook functions. `service.py`
assembles their results for the API. The source notebook SHA-256 is recorded in
the module and every report. The application does not require that notebook at
runtime. Undefined/nonfinite values become JSON null and display as Undefined.

## Definitions

- Activity/object/attachment KL: additive smoothing 0.5, union of categories,
  base-2 logarithms, both directions. Objects without events count as objects;
  duplicate event-object attachments count once in the attachment histogram.
- Timing: rediscover both logs, upper-middle source comparison, population std.
  `minimum` selects minimum–P25; `p25` selects minimum–P50; `p50` selects P25–P75,
  using the notebook's exact inclusive indices. Anchors apply to both logs.
- WMAPE: sum of absolute differences divided by sum of absolute input values,
  over shared activity means/stds, without frequency weighting. Zero denominator
  is undefined. Missing activities are reported.
- W1: empirical distance in hours over all samples already selected by timing
  discovery. At least one sample in each log; anchors excluded. Reports weighted
  (input selected-sample counts), unweighted, and median distances and sample
  coverage. It never reapplies the percentile window.
- Relative NGD: per-object sequences, event-ID tie-break after timestamp,
  n−1 padding on both ends, total variation of normalized histograms, n=2 and 3.
  Reports pooled and per-type results. Empty trace distributions are undefined.
- Confidence: canonical arc orientation, strict EF/EP time comparisons, Cartesian
  Each combinations plus joint All/Any event filters and declared count bounds.
  Unsupported arrows/indirect labels are explicitly unavailable, not skipped.
- Violations: one failure per event–constraint activation; event violation rate
  uses unique affected events and equals one minus global confidence. The
  notebook treats logs as completed; there is no repairability classification.
- Coverage: the notebook's seven independent diagnostics. No overall score.

For models normalized by the UI, retained `from`, `to`, and `counts` are
authoritative, matching the model file used in the notebook. Runtime caps from
`observed_counts` do not replace those bounds. Older editor-only response and
precedence models are explicitly converted to arc orientation from their
source/target fields; their nmin/nmax values supply counts. The actual canonical
evaluation model is included in the downloadable report.

## Verification

Run `python3 -m unittest Backend.tests.test_notebook_evaluation -v` from the
repository root. Golden fixtures were generated by executing the supplied
notebook's cells 9, 11, 14, 16, 18, 20, 23, 25 and 27, changing only the input
paths and timing/anchor settings. They test all three windows and anchors,
including ties, duplicate attachments, unused objects, inactive constraints,
vacuous Each domains, mixed involvement and finite/zero count bounds.

The tests compare numeric outputs with tolerance 1e-12, then separately check
API routing, orientation conversion, undefined results, and unsupported inputs.
